# Ownership & Status Register

## Purpose

Prevent the personal hub from accidentally representing clients, employers, historical concepts or third-party assets as Farouk-owned enterprises.

## Rules

1. Ownership must be evidenced or explicitly confirmed.
2. Employment is not ownership.
3. Client delivery is not ownership.
4. Historical naming is not evidence of current operation.
5. A GitHub repository under an account is evidence of repository control, not necessarily legal ownership of an enterprise, brand or intellectual property.
6. Where ownership is unclear, use **REQUIRES VERIFICATION**.
7. Public-facing pages must not imply current operations when the record only supports historical activity.

## Register

| Asset / Enterprise | Ownership | Status | Evidence needed | Public treatment |
|---|---|---|---|---|
| Farouk Pandor personal brand | Farouk | ACTIVE | Professional record | Public |
| faroukpandor GitHub repositories | Repository account controlled by Farouk | ACTIVE / VARIES | Repository metadata + project records | Public where appropriate |
| Historical strategy names | REQUIRES CONFIRMATION | HISTORICAL | Current ownership/operational evidence | Archive/timeline |
| Client / employer assets | CLIENT / THIRD PARTY where applicable | CLIENT / THIRD PARTY | Engagement/ownership evidence | Clearly attributed; no ownership implication |
| Other enterprises | REQUIRES VERIFICATION | REQUIRES VERIFICATION | Current enterprise evidence | Do not publish as owned until verified |

## Professional-claim guardrail

The site must use only supported professional descriptions. Education, experience and continuing education should be represented according to the evidence available, without upgrading incomplete study, courses or self-reported experience into regulated credentials or licences.
